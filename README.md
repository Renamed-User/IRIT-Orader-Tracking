# IRIT-Order-Tracking

IRIT-Order-Tracking — консольное приложение для учёта заявок на канцелярские товары. Приложение автоматизирует работу с заявками: сотрудники оформляют заявки на товары из каталога, а завхоз обрабатывает их и следит за остатками на складе.

# Возможности

* Авторизация пользователей с разграничением ролей (Сотрудник, Завхоз).
* Регистрация новых пользователей (доступна только Завхозу).
* Просмотр каталога канцтоваров.
* Управление каталогом: добавление, изменение, удаление товаров (Завхоз).
* Управление остатками на складе: поступление и списание (Завхоз).
* Создание заявок с несколькими позициями (Сотрудник).
* Просмотр своих заявок и отслеживание их статуса (Сотрудник).
* Отмена своей заявки, пока она находится в статусе «Новая» (Сотрудник).
* Обработка заявок: одобрение (с проверкой и списанием остатков), отклонение, передача к выдаче и подтверждение выдачи (Завхоз).

# Роли

| Роль | Что может |
|---|---|
| Сотрудник | просматривать каталог, создавать заявки, просматривать свои заявки, отменять свои заявки в статусе «Новая» |
| Завхоз | обрабатывать все заявки, редактировать каталог, менять остатки, регистрировать пользователей |

# Жизненный цикл заявки

| Статус | Что происходит дальше | Кто |
|---|---|---|
| Новая | одобрить → «Сборка» (остатки списываются); отклонить → «Отклонена»; отменить → «Отменена» | Завхоз (одобрить, отклонить); Сотрудник (отменить) |
| Сборка | передать к выдаче → «Готова к выдаче» | Завхоз |
| Готова к выдаче | подтвердить выдачу → «Выдана» | Завхоз |
| Отклонена, Отменена, Выдана | финальные статусы, изменить нельзя | — |

Остаток на складе проверяется при одобрении заявки. Если товара не хватает по какой-либо позиции, Завхоз решает: оставить заявку «Новой» и вернуться к ней позже или отклонить. Проверка остатков, списание и смена статуса выполняются в одной транзакции.

# Архитектура

Приложение многослойное. Слои обращаются только к нижележащим:

```
ui  →  services  →  repos  →  database
```

* **ui** — консольный интерфейс: меню, ввод и вывод. Не содержит SQL и бизнес-правил.
* **services** — бизнес-логика: проверка данных и прав, работа нескольких репозиториев вместе, транзакции. Ошибки сообщаются исключениями. Не содержит SQL.
* **repos** — доступ к данным: единственное место с SQL-запросами, по одному репозиторию на сущность.
* **database** — подключение к SQLite и обёртки над запросами.
* **models** — структуры данных, которыми обмениваются слои.

# База данных

Используется SQLite. Структура описана в `src/database/schema.sql`, схема связей показана в `docs/diagrams/er-diagram.png`.

Таблицы: `roles`, `users`, `categories`, `products`, `request_statuses`, `requests`, `request_items` (позиции заявки, связь «многие ко многим» между заявками и товарами).

Пароли хранятся в виде хэша SHA-256, а не в открытом виде. Это учебная реализация без «соли».

**Внимание:** скрипт `schema.sql` начинается с удаления таблиц (`DROP TABLE`). Его повторное выполнение пересоздаёт базу и стирает все накопленные данные, оставляя только тестовые.

# Сборка и запуск

Проект рассчитан на Windows (для корректного вывода кириллицы в консоли используется `windows.h`). Требуется компилятор с поддержкой C++17 и CMake версии 3.15 или выше.

**Visual Studio:** открыть папку проекта (Файл → Открыть → Папка), дождаться настройки CMake, выбрать цель `IRIT_Order_Tracking.exe` и запустить.

**Командная строка:**
```
cmake -S . -B build
cmake --build build --config Debug
```

Путь к файлу базы данных задаётся при сборке (`DB_PATH` в `CMakeLists.txt` указывает на `src/database/database.db`), поэтому программа находит базу независимо от папки запуска.
